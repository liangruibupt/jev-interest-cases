# P2 · A2 工单分流看板 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the A2 board: 24 English support tickets, one Jev request per ticket with 10 questions (speculative fan-out), pure composition logic (spam risk, confidence gate, priority, cc), a six-lane kanban whose threshold sliders re-route with zero new inference, smoke cases with hand labels, and `docs/scenarios/A2.md`.

**Architecture:** Dataset + questions + thresholds + `compose()` live in `shared/src/scenarios/a2-triage/` and `shared/src/datasets/tickets.ts`. The server route `POST /api/a2/evaluate` builds a minimal state per ticket and fans out through `askJev` (queue limits concurrency to 6), returning raw answers and traces; it does **not** decide lanes. The web page runs `compose()` in the browser over stored answers, so slider changes are instantaneous and cost nothing.

**Tech Stack:** as P0/P1. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-22-jev-lab-design.md` §4 A2, §5 (cost row A2).

## Global Constraints

- English ticket text; Chinese UI. Question IDs are code-only; instructions are complete sentences.
- All thresholds/weights are exported constants (`A2_THRESHOLDS`, `A2_SPAM_WEIGHTS`) and are the *only* knobs the sliders touch.
- `compose()` is pure and deterministic; it must never call the network.
- Normal runs use `cache: "read-write"` (the committed cache lets a fresh clone replay the board without a key).

```ts
export const A2_QUESTIONS: Questions;          // 10 questions, ids below
export type A2QuestionId = "department" | "requested_resolution" | "bug_severity" | "has_repro_steps" | "refund_requested" | "requests_credentials" | "sender_identity_mismatch" | "unexpected_reward" | "mentions_open_order" | "frustration";
export interface A2Thresholds { deptMinConfidence: number; spamReviewLow: number; spamBlock: number; refundYes: number; secondTeamMinProb: number; severityHigh: number; reproYes: number; openOrderYes: number; frustrationHigh: number; }
export const A2_THRESHOLDS: A2Thresholds = { deptMinConfidence: 0.6, spamReviewLow: 0.4, spamBlock: 0.6, refundYes: 0.7, secondTeamMinProb: 0.25, severityHigh: 1.5, reproYes: 0.6, openOrderYes: 0.7, frustrationHigh: 1.5 };
export const A2_SPAM_WEIGHTS = { requests_credentials: 0.45, sender_identity_mismatch: 0.3, unexpected_reward: 0.25 };
export const A2_SLIDERS: { key: keyof A2Thresholds; label_zh: string; min: number; max: number; step: number }[];
export interface Decision { lane: Lane; priority: number; spamRisk: number; badges: ("refund" | "repro" | "open_order" | "angry" | "blocking")[]; ccTeams: Exclude<Lane,"review"|"quarantine">[]; reasons: string[]; usedQuestionIds: A2QuestionId[]; }
export function compose(answers: Answers, thresholds?: A2Thresholds, weights?: typeof A2_SPAM_WEIGHTS): Decision;
export const LANE_LABELS_ZH: Record<Lane, string>;   // billing 账单 / orders 订单 / account 账户 / technical 技术 / review 人工复核 / quarantine 隔离
```

**Questions (exact wording):**

| id | type | instructions | criteria |
|---|---|---|---|
| department | choice | `{question:"Which team should handle \`ticket.message\`?", focus:"Classify the customer's primary request, not every topic mentioned."}` | billing `{what:"Charges, invoices, refunds, subscriptions, prices", not_for:"Order tracking or signing in", examples:["I was charged twice","Where is my refund?","Can I get an invoice?"]}` · orders `{what:"Order status, delivery, cancellation, returns, exchanges", not_for:"Charges or signing in", examples:["Where is my package?","Cancel my order","The item arrived damaged"]}` · account `{what:"Signing in, passwords, 2FA, email changes, permissions, deleting the account", not_for:"Charges or delivery", examples:["I can't sign in","Change my email","Add my teammate"]}` · technical `{what:"Bugs, errors, outages, crashes, API or integration failures", not_for:"Billing or delivery", examples:["The export button crashes","Our API calls return 500"]}` · other `"None of the above"` |
| requested_resolution | choice | "What does the customer want to happen?" | refund "Money back" · exchange "Swap for a different item or size" · replacement "The same item sent again" · fix "A bug, outage, or access problem repaired" · information "Just an answer or a document, no action needed" · other "Something else" |
| bug_severity | score | "If `ticket.message` reports a defect or outage, how severe is it?" | ["Cosmetic; no impact to functionality","Broken or degraded feature, but a workaround exists","Blocking issue; no workaround exists"] |
| has_repro_steps | noul | "Does `ticket.message` describe specific steps to reproduce a problem, or name the environment (browser, device, version)?" | — |
| refund_requested | noul | "Does `ticket.message` explicitly ask for money back or an account credit?" | true "Directly asks for a refund, credit, or money back" · false `{what:"Does not ask for money back", not_for:"A billing complaint or question without a requested remedy"}` |
| requests_credentials | noul | `{question:"Does \`ticket.message\` ask the recipient to disclose a credential listed in \`policy.sensitive_credentials\`?", focus:"A request to send the credential itself, not an instruction to reset or change it."}` | true "Asks the recipient to reply with, type, or send a password, security code, API key, or one-time code" · false "No credential is requested" |
| sender_identity_mismatch | noul | "Does the organization named in `ticket.sender.display_name` conflict with the domain of `ticket.sender.email`?" | true "Claims an organization unrelated to the email domain" · false "The name and domain agree or make no organizational claim" |
| unexpected_reward | noul | "Does `ticket.message` announce an unrequested prize, bonus, or payment for the recipient?" | — |
| mentions_open_order | noul | "Does `ticket.message` refer to one of `customer.open_orders` by id or identifying details?" | — |
| frustration | score | "How frustrated does the customer appear in `ticket.message`?" | ["Calm and matter-of-fact","Frustrated but civil","Very angry, hostile, or threatening to leave"] |

**compose() rules (in order):**
1. `spamRisk = Σ weights[id] · noul(id)` over the three phishing Nouls. `spamRisk ≥ spamBlock` → lane `quarantine`; `spamReviewLow < spamRisk < spamBlock` → lane `review` (reason "垃圾风险 x 在灰区").
2. `department.choice === "other"` or `department.confidence < deptMinConfidence` → `review` (reason with the number).
3. Else lane = department. `ccTeams` = other departments (not `other`) with probability ≥ `secondTeamMinProb`.
4. `priority = 0.5·(frustration.score/2) + 0.5·(lane==="technical" ? bug_severity.score/2 : 0)` rounded to 2 dp.
5. Badges: `refund` if `refund_requested ≥ refundYes`; `repro` if lane technical and `has_repro_steps ≥ reproYes`; `open_order` if `mentions_open_order ≥ openOrderYes`; `angry` if `frustration.score ≥ frustrationHigh`; `blocking` if lane technical and `bug_severity.score ≥ severityHigh`.
6. `usedQuestionIds`: always department, frustration, the three spam Nouls; plus `refund_requested` when lane ∈ {billing, orders, review}; `bug_severity`, `has_repro_steps` when lane technical; `mentions_open_order` when lane orders; `requested_resolution` when lane ∈ {billing, orders}.
`reasons` is a Chinese list explaining each rule that fired.
