# P13 · C4 VPP 调度通知与告警 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the C4 page: 12 synthetic grid-operator / aggregator / telemetry / customer notices are judged against 3 virtual-power-plant sites. For every (notice, site) pair one Jev request answers 8 questions — notice type, applies to the site's zone, applies to the site's asset kind, names the site, requires action, is a test, urgency, alarm category — and code parses capacity thresholds (kW / MW), curtailment percentages and time windows from the text and compares them with the site profile. A pure `applyNotice()` routes each pair to 立即行动 / 排期 / 仅告知 / 测试确认 / 告警 / 不适用 / 复核. The page is a notices × sites matrix.

**Architecture:** `shared/src/datasets/vppNotices.ts` (3 sites, 12 notices with expected routes per site) and `shared/src/scenarios/c4-vpp/{questions,thresholds,constraints,compose,index}.ts`. `POST /api/c4/apply` fans out one Jev request per pair (36). Pure Jev.

**Spec:** `docs/06-行业场景适用性.md` (能源 VPP row).

## Global Constraints

- Jev judges text applicability (zone words, asset words, action words). kW / MW thresholds, percentages and clock times are parsed and compared in code — Jev is only asked whether the notice applies to the asset kind and zone.
- Thresholds: `act 0.7 / review 0.35 / urgencyNow 1.5 / namesSiteMin 0.5` (alarms and customer requests are judged by `names_site` alone; zone/asset words do not apply to them). The applies_region / applies_asset criteria say a notice that does not limit itself to a zone / kind applies everywhere.
- Synthetic English notices, fictional sites; Chinese UI. Cache read-write for the 36 pairs; `live` bypasses.

### Task 1: shared

```ts
export interface VppSite { id: string; name: string; region: string; asset_type: "battery_storage" | "solar_plus_storage" | "demand_response_load"; capacity_kw: number; note_zh: string }
export type C4Route = "act_now" | "schedule" | "info" | "acknowledge_test" | "alarm" | "not_applicable" | "review";
export interface VppNotice { id: string; from: "grid_operator" | "aggregator" | "telemetry" | "customer"; text: string; expected: Record<string /* site id */, C4Route[]>; note_zh: string }
export const VPP_SITES: VppSite[]; export const VPP_NOTICES: VppNotice[];
export const C4_QUESTIONS: Questions;   // notice_type, applies_region, applies_asset, names_site, requires_action, is_test, urgency, alarm_category
export function buildPairState(n: VppNotice, s: VppSite): { notice: string; from: string; site: { name: string; region: string; asset_type: string } };
export const C4_THRESHOLDS = { act: 0.7, review: 0.35, urgencyNow: 1.5 };
export interface Constraint { kind: "min_capacity_kw" | "curtail_percent" | "time_window" | "deadline"; text: string; value?: number; satisfied?: boolean }
export function parseConstraints(text: string, site: VppSite): Constraint[];   // "≥ 1 MW" → min_capacity_kw 1000, satisfied = site.capacity_kw >= 1000
export interface PairDecision { route: C4Route; ruleId: string; rule_zh: string; reasons: string[]; applies: number /* min(region, asset) or names_site */; noticeType: { choice: string; confidence: number } | null; alarmCategory: string | null; urgency: number; requiresAction: number; isTest: number; constraints: Constraint[] }
export function applyNotice(answers: Answers, notice: VppNotice, site: VppSite, t?: typeof C4_THRESHOLDS): PairDecision;
export const C4_ROUTE_LABELS_ZH: Record<C4Route, string>; export const C4_NOT_ASKED: { question: string; why_zh: string }[];
```

Rules (ordered): a capacity constraint the site does not satisfy → not_applicable (code) · names_site ≥ act → applicable; else applicable iff applies_region ≥ act and applies_asset ≥ act; if either is in [review, act) → review · not applicable → not_applicable · is_test ≥ act → acknowledge_test · alarm_category ≠ not_an_alarm with confidence ≥ act (or notice_type alarm) → alarm · requires_action ≥ act → urgency ≥ urgencyNow ? act_now : schedule · else info.
