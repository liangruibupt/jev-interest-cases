# 02 · 置信度与阈值

## confidence 是什么

Choice 和 Score 的答案都带 `probabilities`（全分布）与 `confidence`（0–1）。**confidence 是从分布的形状算出来的**：概率集中在一个选项/等级 → 高；分散 → 低。它描述"模型对这个答案有多确定"，不是"答案正确的概率"，更不是"允许你行动"的许可。

Noul **没有** confidence：它本身只有两个结果，`noul` 这个数已经完整描述了分布（0.95 = 很确定是；0.5 = 一半一半）。

## 校准意味着什么

Jev 用 RLCD 训练，目标是**校准**：在一大批预测里，标 0.8 的事件应约有 80% 真的发生。校准是**群体性质**，不保证单条答案正确。这正是它对软件有用的原因：概率可以直接当作可信度来做决策。

## 三段式：高 → 自动，中 → 确认，低 → 人工

```python
if answer.confidence < 0.5:        # 模型自己都不确定，不要猜
    route_to_human()
elif answer.choice == "check_balance":
    show_balance()                 # 低风险，0.5 以上就够
elif answer.choice == "approve_transfer":
    if answer.confidence > 0.9:    # 高风险 + 高置信 → 执行
        confirm_then_execute()
    else:                          # 高风险 + 中置信 → 先确认
        ask_user_to_confirm()
```

**阈值不是一个数**：同一系统里不同动作按后果设不同门限。查余额错了只是多听一遍；转账错了要赔钱。

## Noul 的阈值

```python
YES, NO = 0.8, 0.2
if NO < noul < YES: send_to_review()   # 中间区间交给人
elif noul > YES: act()
```
误报代价高（发工单、退款）→ 提高 YES；漏报代价高（安全问题）→ 降低 YES。

## 别把不同问法的数字互相套用

官方明说没有"结构不变量"：同一条工单，Noul "要退款吗" = 0.22，而二选一 Choice 的 `yes` = 0.01；"要退款" 0.72 与 "要的不是退款" 0.47 之和 ≠ 1。**在 Noul 上调好的阈值不能搬到 Choice 上**，也别指望两个独立问题的概率满足算术恒等式。

## 在本项目里

- 所有阈值都是 `shared/src/scenarios/*/thresholds.ts` 里的常量，UI 可见可调。
- A2 工单看板：拖动置信度门限、垃圾邮件上下限，工单**不重新推理**即重排。
- B1 护栏路由：strict / permissive 两套阈值切换。
- B4 智能家居：开锁动作要求 confidence ≥ 0.85，其余动作 0.5–0.6。
