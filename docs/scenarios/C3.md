# C3 · 公告重大性判断（金融）

**目标**：把"金融判断"里 Jev 能做的那一层拆出来：**判断公告说了什么、说得多重大、怎么说的**，不判断价格、估值或涨跌。15 条关于虚构公司的公告（8-K 事项、新闻稿、简讯），每条一次 Jev 请求、8 个问题：事件类型 Choice（13 类）、重大性 Score（4 级情境描述）、对股东的方向 Choice、是否前瞻性、措辞是否含糊、是否涉及会计 / 内控、是否涉及关键人物、是否套话。代码按规则排成**立即看 / 今日看 / 归档**；金额与百分比由代码提取只作展示。页面右下方列出刻意没有问的问题。

页面：`/c3`。代码：`shared/src/datasets/filings.ts`、`shared/src/scenarios/c3-filings/{questions,thresholds,numbers,compose}.ts`、`server/src/routes/c3.ts`（`POST /api/c3/judge`）、`web/src/pages/C3Filings.tsx`。纯 Jev。

## 发给 Jev 的东西

**state**：`{ company, source, headline, text }`。

| id | 类型 | 英文原文（节选） | 用途 |
|---|---|---|---|
| event_type | Choice（13 类） | What kind of event does `text` announce? · guidance_change / executive_change / restatement_or_accounting / going_concern_or_liquidity / m_and_a / major_customer_or_contract / litigation_or_regulatory / cyber_incident / capital_return / product_or_operations / insider_transaction / routine_housekeeping / other | 分类 |
| materiality | Score（4 级） | How significant is the event in `text` for the company's business? · 常规事务 / 值得注意但在预期内或规模小 / 对业绩、经营、领导层或重大产品 / 客户有显著影响 / 可能改变估值或持续经营 | 排序与泳道 |
| direction | Choice | …is the news good or bad for the company's shareholders? · negative / neutral / positive / mixed | 方向 |
| is_forward_looking | Noul | …mainly announce expectations, plans, or intentions rather than events that have already happened? | 标记 |
| hedged_language | Noul | …vague, evasive, or unusually hedged wording… ('certain matters', 'in due course', 'other opportunities' with no detail)? | 标记 / 提升 |
| accounting_or_controls | Noul | …financial reporting errors, a restatement, an auditor change, or internal-control weaknesses? | 硬规则 |
| key_person | Noul | …departure, arrival, conduct, or transactions of a CEO, CFO, board member, or other named key person? | 标记 |
| boilerplate | Noul | Is `text` mostly standard boilerplate…? | 下沉 |

**刻意没有问的**：该不该买？被低估了吗？明天会涨吗？盈利会掉多少？——买卖取决于价格与仓位，估值是数字与模型，涨跌是预测，金额只由代码提取。

## 规则（`compose.ts`，顺序首中）

| # | 规则 | 泳道 |
|---|---|---|
| 1 | accounting_or_controls ≥ 0.7 | 立即看（会计问题永远先看） |
| 2 | materiality ≥ 1.8 | 立即看 |
| 3 | key_person ≥ 0.7 且方向为负面 | 立即看 |
| 4 | boilerplate ≥ 0.7 且 materiality < 1.1 | 归档 |
| 5 | materiality ≥ 1.1 | 今日看 |
| 6 | hedged_language ≥ 0.6 且 materiality ≥ 0.8 | 今日看（含糊措辞值得一读） |
| 7 | 其余 | 归档 |

### 一次基于数据的调门限

设计稿把"立即看"定在 materiality ≥ 2.3、"今日看" ≥ 1.2。第一次关缓存运行后发现 Jev 把下调指引（1.88）、败诉（2.16）、失去最大客户（2.02）都放在"显著影响"这一档（2）附近而不是 3——按四级描述这是对的：只有持续经营疑虑（3.00）和 12 亿美元并购（2.46）才接近"可能改变估值"。于是把门限改为 **1.8 / 1.1**，让"显著"档稳稳进入立即看。同时把回购授权（0.94）的标注从"今日看｜立即看"放宽为"今日看｜归档"：materiality 问的是"对公司业务"的影响，回购不改变经营，Jev 给 0.9 是按字面回答了问题——是我们的标注在用股东视角。这与 B1 调 Opus 门限是同一件事：先看分布，再把门限写进代码，并把理由写下来。

- **事件类型 15/15 全对，置信度全部 1.00**：13 类封闭清单加描述，对结构化公告几乎没有歧义。
- **泳道 15/15**（调门限前 10/15）。两轮 materiality 相差 ≤ 0.07，说明分布稳定、是门限而不是模型在变。
- **F12 是 hedged_language 的展示**："except as described"、"certain matters"、"in due course" 让含糊度到 0.86；即使 materiality 只有 0.91，会计规则也把它送到立即看。
- **F02 的方向只有中性 0.33**：CFO"即刻离职去追求其他机会"配上标准的"无分歧"声明，Jev 在负面 / 中性之间分票，含糊度 0.51——这正是人应该读的那种公告。
- **F13 的 key_person 0.94 但没有触发规则 3**：内部人卖出的方向是中性，规则 3 要求负面；它按套话 0.72 归档。

## 试一试

1. 把"立即看"门限拉到 2.3（设计稿的值），看 F01 / F08 / F09 / F14 掉到今日看——再想想四级描述里"显著影响"到底该进哪个泳道。
2. 把"标记 Noul ≥"拉到 0.9：F02 的 key_person 0.99 仍在，F12 的含糊 0.86 掉出标记但会计 0.97 仍把它送到立即看。
3. 对比 F05 与 F07：同是 capital_return，5 亿回购 0.91 与分红不变 0.12 的差别由情境描述体现。
4. 改 `materiality` 的问题为 "for the company's shareholders"，看 F05 会不会升到今日看——问法决定答案。

## 陷阱

- 这不是投资建议：Jev 判断公告说了什么、说得多重大，不判断股价会怎样。
- 虚构公司与合成文本；真实公告更长、更套话，先在样本上校验 boilerplate 与 materiality 的分布再定门限。
- 事件类型是封闭清单：清单外只能落到 other。
- 门限附近会漂移：F06（1.01）与今日看门限 1.1 只差 0.09，两轮里它一直在归档，但别指望永远如此；立即看 / 今日看之间的公告都值得看一眼。
