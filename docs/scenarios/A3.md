# A3 · 文档逐行语义搜索（无 embedding、无生成）

**目标**：把整篇 GitHub 服务条款（218 行、约 12k tokens）作为 state 一次发给 Jev，用一个 **218 选项的 Choice** 给每一行相关度概率，用一个 **存在性 Noul** 回答"文档里到底有没有答案"，再加一个 speculative Noul 判断答案是否跨多行。没有向量索引、没有 LLM 生成——检索结果就是一组可阈值化的概率。

页面：`/a3`。代码：`shared/src/datasets/githubTos.ts`（218 行，CC0）、`shared/src/scenarios/a3-semantic-find/{buildState,questions,thresholds,compose}.ts`、`server/src/routes/a3.ts`（`POST /api/a3/search`）、`web/src/pages/A3SemanticFind.tsx`。

## 发给 Jev 的东西

**state**：整篇文档，每行前缀行号：

```
L000| GitHub Terms of Service
L001| Thank you for using GitHub! …
…
L217| …
```

**3 个问题（一次请求）**：

| id | 类型 | 英文原文 | 用途 |
|---|---|---|---|
| where | Choice（218 选项 `L000`…`L217`，无描述） | Which line of the document contains the answer to: "{query}"? | 每行的相关度概率 |
| exists | Noul | Does any line of the document address or answer: "{query}"? · true "At least one line states or directly implies the answer" · false "No line addresses this question" | 文档是否涉及 |
| spans_multiple | Noul（speculative） | Is the answer to "{query}" spread across more than one line of the document? | ≥ 0.6 时高亮 top-3 而不是 top-1 |

**组合**（`compose.ts`）：`exists ≥ 0.7` → 文档已回答；`≤ 0.35` → 文档未涉及；之间 → 部分涉及。`ranked` = 概率 ≥ 0.03 的前 5 行。`naiveTop` 永远存在——它就是"只看 Choice"会给出的答案。

## 为什么必须有 exists

Choice 的概率和恒为 1。问"哪一行包含仲裁条款的答案"，即使文档根本没有仲裁条款，Jev 也会把概率分给最接近的几行（管辖法律、诉讼地点）。页面上的"忽略 exists"开关就是为了让你看见这个陷阱：

| 查询 | 只看 Choice（天真结论） | 加上 exists |
|---|---|---|
| do I have to take disputes to arbitration? | 答案在 L205（0.46–0.54，"governed by the federal laws… courts located in San Francisco"） | exists 0.40 / 0.34 → **部分涉及 / 未涉及** |
| can I use GitHub for cryptocurrency mining? | 答案在 L043（0.35–0.38，"must not violate any applicable laws"） | exists 0.07 → **文档未涉及** |

## 实测：6 条示例查询（2026-09-23，Jev 关缓存，两次运行）

| 查询 | 判定 | exists | spans | top 行 | top 概率 | 延迟 |
|---|---|---|---|---|---|---|
| who owns the code I upload? | 文档已回答 | 0.99 / 0.99 | 0.74 / 0.76 | **L052** "You own Your Content…" | 0.47 / 0.50 | 870 / 798 ms |
| can GitHub kick me off the platform without warning? | 文档已回答 | 0.98 / 0.98 | 0.75 / 0.72 | L168 "GitHub has the right to suspend or terminate your access…" | 0.96 / 0.98 | 598 / 471 ms |
| do I have to take disputes to arbitration? | 部分涉及 / 未涉及 | **0.40 / 0.34** | 0.23 / 0.25 | L205（管辖法律与法院） | 0.54 / 0.46 | 473 / 497 ms |
| can minors use GitHub with parental permission? | 文档已回答 | 0.77 / 0.76 | 0.69 / 0.63 | L029 "You must be age 13 or older…" | 0.97 / 0.98 | 484 / 567 ms |
| can I use GitHub for cryptocurrency mining? | 文档未涉及 | 0.07 / 0.07 | 0.24 / 0.23 | L043 "must not violate any applicable laws" | 0.35 / 0.38 | 556 / 474 ms |
| what happens to my data if I delete my account? | 文档已回答 | 0.98 / 0.98 | 0.95 / 0.94 | L164 "We will retain and use your information as necessary…" | 1.00 / 1.00 | 532 / 467 ms |

- cookbook 的两条主查询完全复现：ownership → **L052**，terminate → L168；每次请求 12,031–12,043 tokens、**$0.000505**，两轮 p50 分别 556 ms 与 497 ms。
- ownership 的概率分散在 L052（0.47）/ L053 / L046 / L051 之间，`spans_multiple` 0.74–0.78 → 页面高亮 top-3：所有权条款确实由"短版说明 + 标题 + 两条正文"组成。
- 仲裁查询是**贴着门限**的例子：exists 两次分别 0.40 与 0.34，跨过了 0.35 的"未涉及"线。文档确实谈了争议怎么处理（法院、管辖法律），只是没有仲裁——"部分涉及"也是合理判定。我们把示例的预期从单一状态改为集合（未涉及 | 部分涉及），并保留这个例子提醒：靠近门限的查询在两次运行间会漂移（见 A4 的漂移数据），需要人工确认或更宽的灰区。
- minors 一例 cookbook 描述为"部分涉及"，Jev 给 exists 0.77：文档明确规定 13 岁以上，只是没提家长许可。这是措辞问题——问"parental permission"还是问"age"，答案会不同。

### 页面上的一次查询

ownership：1.01 s（首次，含网络）、12,031 tokens、$0.000505；top-5 = L052 0.33、L053 0.23、L046 0.23、L051 0.20（同一查询不同运行的概率会有 ±0.15 的变化，但排名首位稳定）。

## 成本对比（诚实版）

| 对比对象 | 每次查询 | 说明 |
|---|---|---|
| Jev（本场景） | **$0.000505**（≈12k tokens） | 每次都把整篇文档发过去 |
| Claude Sonnet 5 读全文并指出行号 | ≈ $0.025 | 6 条实测：$0.1505 vs $0.0030 → **98.0%（50×）** |
| Claude Opus 5 | ≈ $0.063 | 125× |
| 向量检索（embedding） | ≈ $0.0000002 + 一次性索引 ≈ $0.0002 | **Jev 并不更便宜**（每查询贵约三个数量级） |

Jev 相对向量检索的优势不在价格，而在：零索引、零冷启动（文档一变马上可查）、交叉编码级的理解（查询与每一行一起被阅读，而不是各自编码后比距离）、可解释的概率、以及"文档没有答案"这个向量检索给不出的结论。适合小文档、高频变化、需要"不存在"判断的场景；文档超过 255 行就要先分段。

## 试一试

1. 打开"忽略 exists"，对比仲裁查询与加密货币查询：天真结论都会给出一行，exists 分别说 0.40 / 0.34 与 0.07。
2. 把 "who owns the code I upload?" 改成 "who licenses the code I upload?"，看概率如何从 L052 移向 L053/L055（许可条款）。
3. 问一个自由问题（≤ 200 字符，英文）：自由问题不会写入提交的缓存，每次约 $0.0005。
4. 把 `A3_THRESHOLDS.absent` 调到 0.45，仲裁一例会稳定落到"未涉及"——门限是产品决策，不是模型决策。

## 陷阱

- 每次查询 12k tokens：文档大 10 倍就不划算了，先按段落粗筛（B3 的做法）再逐行。
- Choice ≤ 255 选项：更长的文档要分块、再合并各块的 exists。
- Jev 按字面理解：问法里的词直接决定它挑哪一行；同一意图换一种问法要重新校验。
- 门限附近会漂移：exists 在 0.3–0.45 之间的查询别自动下结论。
