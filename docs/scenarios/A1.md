# A1 · 原语实验室

**目标**：亲手看到三种原语（Choice / Score / Noul）返回什么，感受一次请求多题并行与约 0.5 秒的响应，并用 7 组预置理解 Jev 的几个关键行为。

页面：`/a1`。代码：`shared/src/scenarios/a1-playground/presets.ts`（预置）、`server/src/routes/a1.ts`（`POST /api/a1/evaluate`，≤12 题、state ≤12k 字符）、`web/src/pages/A1Playground.tsx`。

## 可视化约定

- **Choice**：横条 = 每个选项的概率；被选中项用 Jev 蓝，其余降为灰（强调而非多色）；右上角圆环 = confidence。
- **Score**：每级一条概率横条（最高级用蓝），下方数轴 0…n−1 上的蓝线 = 概率加权的 `score`，可以落在两级之间。
- **Noul**：仪表条，蓝色填充到概率值，两条细线是代码里的 NO ≤ 0.2 / YES ≥ 0.8 门限；Noul 没有 confidence。
- 文字一律墨色，不用数据色着色；hover 显示精确数值。

观察：
- 预置 5 几乎精确复现官方文档的数字（0.55/0.33 vs 0.0/1.0）。
- 预置 7 提醒我们：单个样本不能证明"中文更差"；官方声明 CJK 整体准确率较低，要用自己的数据评估。
- 稳定延迟 340–620ms，其中约 300ms 是本地到 API 的网络往返。

## 成本对比（页面 SavingsCard，预置 1）

同样 425 个输入 tokens 若交给 Claude Sonnet 5 做结构化输出（假设输出 150 tokens）：$0.0023；Jev：$0.000018；**节省 99.24%（132×）**。切换基线到 Opus 5 约 330×。

## 试一试

1. 把预置 1 的 state 改成 `Thanks, that fixed it!`，看 is_urgent 掉到 0.0x。
2. 把预置 5 的三条情境描述改成 `Low / Medium / High`，看置信度如何下降。
3. 预置 6 的 state 改成边界句 `Can I still send these back if I wore them once? It's been a week.`，比较两版分布。
4. 开"实时模式"，逐字修改 state，感受响应节奏。
5. 加一个 Choice，选项超过 255 个或 Score 超过 10 级，看客户端校验如何拦住它。

## 陷阱

- Noul 0.5 = 是否各半，不是"中等"。
- 反向问法与正向问法的答案不保证互补（本例 0.99 / 0.01 只是碰巧互补）。
- 数数、算数、日期比较留给代码。
- 问题 ID 不发给模型：`is_urgent` 这个名字对 Jev 不存在，instructions 必须写全。
