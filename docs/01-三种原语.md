# 01 · 三种原语：Choice、Score、Noul

每次请求 = 一个 `state`（要评估的内容）+ 一组带 ID 的 `questions`。每个问题是三种类型之一，答案按同样的 ID 返回。**问题 ID 不会发给模型**，所以问题文本必须自成一体。

## 请求与返回

| 类型 | 问什么 | `criteria` | 返回字段 |
|---|---|---|---|
| **Choice** | 在给定集合里选一个 | `{ 选项: 描述 \| null }`，≤ 255 个 | `choice`（最高概率选项）、`probabilities`（和为 1）、`confidence` |
| **Score** | 在有序量表上的位置 | 有序数组，2–10 级，每级描述一种**情境** | `score`（概率加权，可落在两级之间）、`legend`、`probabilities`、`confidence` |
| **Noul** | 是 / 否 | 可选 `{ true: 描述, false: 描述 }` | `noul`（是的概率，0–1；**没有** confidence） |

```json
{
  "state": "Hi, I've been trying to connect my Stripe account for 3 days ... Please help ASAP.",
  "model": "jev-latest",
  "questions": {
    "department": { "type": "choice", "instructions": "Which team should handle this", "criteria": { "billing": "Payment or subscription issues", "technical": "Bugs or integration problems", "sales": "Pricing or account questions" } },
    "frustration": { "type": "score", "instructions": "How frustrated the customer appears", "criteria": ["Calm, just stating facts", "Frustrated but civil", "Very angry, strong language"] },
    "is_urgent": { "type": "noul", "instructions": "The message conveys urgency or time-sensitivity" }
  }
}
```

## 选型规则

- 答案是**无序集合中的一个** → Choice。列表可能覆盖不全时加 `other` / `none_of_the_above`。
- 答案是**有序量表上的位置** → Score。级别要写"情境"，不要写"程度"："Broken, but a workaround exists" 好；"Moderately severe" 差；只写数字 `["0","1","2"]` 最差（官方示例：同一条报告从 0.0/置信 1.0 变成 0.55/置信 0.33）。
- 答案是**是否** → Noul。**Noul 的 0.5 表示"是与否各半"，不是"中等程度"**；要量程度请用 Score。
- 两种都行时，选代码能直接消费的那种：Choice 对应分支，Score 对应阈值，Noul 对应 `if`。

## 让问题更准的三个手段

1. **结构化 state**：用 JSON 对象给每部分命名，在问题里用反引号路径引用：`` Does `ticket.messages[0].text` request a refund? ``。
2. **结构化 criteria**：选项容易混淆时，用 `{ what, not_for, examples }` 描述每个选项（字段名自定，模型能看到字段名）。
3. **拆问题**："Is this spam?" 拆成 requests_credentials / sender_identity_mismatch / unexpected_reward … 若干个 Noul，再在代码里加权。原子问题能单独检验、调参、复用。

## 一次请求问很多

同一 state 的所有问题放在**一次请求**里：并行评估、互相不可见、几乎不增加延迟。官方 cookbook：13 题打包比 13 次单发便宜 12.2 倍、快 10 倍，答案不变。只有当下一问题需要**用上一答案构造新的 state 或新的选项**时，才发第二次请求。

## 在本项目里

- A1：三种原语的实时可视化与 7 组预置对照（含"数字级别 vs 情境级别"、"数数陷阱"、"反向 Noul"）。
- A2：10 题一次请求的 speculative fan-out。
- A3：218 个选项的 Choice + 存在性 Noul。
