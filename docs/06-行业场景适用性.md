# 06 · 行业场景适用性：哪些判断能交给 Jev

前八个场景验证的是模式；这一篇回答"我的行业能不能用"。判断标准只有一条：**Jev 做的是"细心读者只凭这段文字、用常识就能下的类型化判断"**。它不看图、不算数、不比时间、不做多步专业推理、不生成。于是每个行业的"判断"都要拆成三类：

| 判断类型 | 例子 | Jev |
|---|---|---|
| 关于文字说了什么 | 这段是否描述了危险、属于哪一类、是否与规则一致、语气是否紧急 | **擅长**：这就是它的设计目标 |
| 需要专业知识或多步推理 | 这组症状是否符合某个诊断、这条披露是否构成会计舞弊 | **弱**：官方 jaggedness 明写多跳推理弱、按字面理解、没有知识检索 |
| 需要数字、物理、时间或感知 | 35 米 20 m/s 能否刹住、现价是否低估、化验值是否超标、现在放电是否划算 | **不能**：不比较数字、不看时间、不读图 |

## 五个行业的拆解

| 行业 | 能交给 Jev 的判断 | 不能交给 Jev 的判断 | 本仓库的实现 |
|---|---|---|---|
| **教育** | 作业是否满足每条评分细则（Noul）、整体水平（情境化 Score）、是否含常见错误概念（Choice）；低置信度交老师 | 数学题算得对不对（代码 / LLM 验算）；句子数（代码数） | **C1 作业按细则评分**：Jev 评分 + Claude 写反馈 + Jev 核验反馈 |
| **医疗** | 患者留言的紧急度、该转哪个科、是否提到胸痛 / 呼吸困难 / 自伤等红旗、是否在索要用药建议 | 是不是某个病（专科多步推理）、化验值是否超标（代码比较）、最终处置（医生） | **C2 患者留言分诊**（规划中，P11）：Score + 红旗 Noul + 硬规则；数值由代码比较；页面明示"没有问 Jev 的问题" |
| **金融** | 公告 / 新闻属于哪类事件、对经营有多重大、是否涉及会计与内控、管理层是否含糊其辞、是否套话 | 该不该买、估值高低、会不会涨（价格、仓位、时间序列） | **C3 公告重大性判断**（规划中，P12）：批量判定成待阅列表；页面明示不问价格与买卖 |
| **能源 VPP** | 调度通知是否适用于本站点、告警 / 工单文本分类、客户是否表达退出意向 | 现在是否放电、报什么价、负荷预测（优化与数值） | **C4 VPP 调度通知与告警**（规划中，P13）：每对（通知 × 站点）判断区域 / 资产是否适用、是否要求行动、是否测试、属于哪类；kW 与时间窗由代码解析比较 |
| **自动驾驶** | 离线分类：脱离报告 / 仿真日志是否描述险情、是否涉及弱势道路使用者、原因属于感知还是规划 | 一切在线驾驭决策：感知是图像，刹不刹车是物理与数字，延迟 0.4–0.8 s 且运行间漂移，也无安全认证 | 未单独实现：适用部分是离线文本分流，模式与 C2 相同 |

## 三条实践规则（来自前八个场景的实测）

1. **进入高风险领域前先量准确率**。我们对每个场景都先用标注集跑冒烟（24 条工单、16 条消息、20 条指令、12 篇作业），再定门限。Jev 的校准是通用的，不是你领域的。
2. **门限附近会漂移**：A3 仲裁查询 exists 0.34 / 0.40，B3 博客段 0.67 / 0.72。有后果的判断要留灰区给人，这是设计而不是缺陷。
3. **代码先行**：数字（B4 的正则、C2 的化验值）、字符串匹配（B2）、句子计数（C1）都在 Jev 之前或之外完成。Jev 只回答"有没有提到"。

一句话：**判断"文字说了什么"交给 Jev，判断"世界是什么样"交给数字和专家，代码负责把两者接起来。**
