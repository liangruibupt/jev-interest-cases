# 07 · 部署到 AWS（CloudFront → S3 / API Gateway → Lambda）

本地开发是 Vite + Hono 两个进程；云端把它们拆成静态站与无服务器 API，放在同一个 CloudFront 分发后面：

```
浏览器 ──HTTPS──► CloudFront（默认域名 d…cloudfront.net）
                    ├── 默认行为  ──► S3（私有桶，Origin Access Control）   静态文件 web/dist；无扩展名路径由 CloudFront Function 改写到 /index.html（SPA）
                    └── /api/*    ──► API Gateway（HTTP API） ──► Lambda（Node 22，Hono `handle(app)`）
                                       CloudFront 注入 x-origin-verify 头；Lambda 校验不通过一律 403 → 直连 execute-api 域名不可用
```

代码：`infra/`（CDK v2，TypeScript）、`server/src/lambda.ts`（Lambda 入口）、`server/src/lib/guards.ts`（三层守卫）。

## 为什么是这个形态

- **不用 Lambda Function URL**：Function URL 是公网可直达的 Lambda 入口，会触发安全审计；API Gateway 放在 CloudFront 后面并做来源头校验，是更常规的公网暴露方式。
- **不用 AgentCore Runtime**：它托管的是通过 `InvokeAgentRuntime`（SigV4 / JWT）调用的 agent 容器，不是普通 HTTP 源，也不托管静态站。
- **API Gateway HTTP API 的限制**：单次请求最长 30 s、不支持流式响应。本项目里只有 A4 的 SSE 实验跑得久，公网模式下它本来就该关闭（单次约 $1.5）；其余接口都在几秒内返回，Bedrock 偶发 > 30 s 的离群会得到 504。

## 公网演示的三层守卫（`guards.ts`）

| 守卫 | 环境变量 | 行为 |
|---|---|---|
| 来源校验 | `ORIGIN_VERIFY_SECRET` | CloudFront 以自定义源头注入 `x-origin-verify`；不匹配 → 403 |
| 公网模式 | `PUBLIC_MODE=1` | `GET /api/a4/run` → 403，只允许回放 `docs/results/` 里已保存的实验 |
| 花费上限 | `MAX_DAILY_USD`（默认 5） | 进程内累计 Jev + Claude 花费达到上限 → 429（`/api/health`、`/api/usage` 不受限） |

上限是**每个 Lambda 实例**的进程内计数：预留并发 5，最坏情况约 5 × 上限；Lambda 实例回收后重新计数。要做全局精确的每日上限需要外部存储（如 DynamoDB），这是演示的有意简化。预置示例全部命中随包发布的只读缓存（`server/.cache/jev`，约 280 条），不产生费用；自由输入的 Jev 调用每次 ≤ $0.0005，Claude 调用 $0.002–0.03。

本地不设这些变量时三层守卫都不生效，行为与之前完全一样。

## 部署步骤

前置：`aws configure` 已有 `global_ruiliang` profile（账号 710299592439），目标区域 `us-east-1` 已 `cdk bootstrap`（该账号的引导栈用了自定义 qualifier `mdi2024`，`infra/bin/app.ts` 默认按它合成；换账号时设 `CDK_QUALIFIER`）。

```bash
# 1) .env 里除 TYPESAFE_API_KEY 外，再放一个随机串（CloudFront 与 Lambda 共享的来源校验头）
echo "ORIGIN_VERIFY_SECRET=$(openssl rand -hex 24)" >> .env

# 2) 从干净的检出构建并部署（避免把工作区里未提交的内容发出去）
git worktree add /tmp/jev-deploy main && cd /tmp/jev-deploy && npm ci
set -a; source /Users/ruiliang/Documents/workspaces/jev-interest-cases/.env; set +a
AWS_PROFILE=global_ruiliang npm run deploy          # = vite build + cdk deploy --require-approval never

# 3) 输出里的 SiteUrl 就是站点地址；ApiGatewayDomain 直连会 403
```

Lambda 打包（`NodejsFunction`，esbuild）把 `server/src` 与 `shared/src` 一起编成 ESM 单文件，并把 `server/.cache/jev`、`docs/results/a4-*.json` 拷进包内（`/var/task/cache/`、`/var/task/results/`）；缓存目录只读，写入静默跳过。`TYPESAFE_API_KEY` 以 Lambda 环境变量存放（静态加密）；生产环境应改为 Secrets Manager 在冷启动时读取。

更新：改代码后再次运行 `npm run deploy`；CDK 只替换变化的资源并自动失效 CloudFront 缓存。下线：`npm run destroy -w @jev/infra`（桶设置了自动清空）。

## 费用

CloudFront 与 Lambda 在免费额度内几乎为零；API Gateway HTTP API $1 / 百万请求；S3 几 MB。真正的成本是访客触发的 Jev / Claude 调用，受花费上限约束。

## 与本地的差别

| | 本地 `npm run dev` | 云端 |
|---|---|---|
| 缓存 | 读写，新的预置结果写回仓库 | 只读，随包发布 |
| A4 实验 | 可跑真实实验并导出结果 | 只回放已保存结果 |
| 单请求上限 | 无 | 30 s（API Gateway） |
| 花费 | 无上限 | 每实例 `MAX_DAILY_USD` |
| 端口 | 5173 / 8787（仅回环） | CloudFront 域名 |
